# 2K HiDPI 助手

一个只管理 macOS 显示分辨率的菜单栏工具。默认直接选择系统实际提供的 HiDPI 分辨率；缺少档位时可明确授权安装物理显示器缩放配置。虚拟镜像只作为手动开启的实验性兼容选项，不再自动启用。

Resolution-only macOS utility for choosing HiDPI modes. The tested Sculptor 2560×1600 path provides 1600×1000 at 120Hz without a virtual display or mirroring. Other hardware still requires verification.

## 功能

- 自动读取显示器型号；同名屏幕按设备身份添加编号，避免所有屏幕都显示为“外接显示器”。设备标识稳定时编号不受枚举顺序影响；同型号屏幕增减或无法提供唯一标识时编号可能变化。
- 主窗口和菜单栏提供可点击的屏幕示意图，呈现屏幕比例、桌面相对位置、编号与主屏星标；点击只选择屏幕，不修改排列。
- 每台屏幕只有一个 HiDPI 分辨率菜单，按物理屏幕比例推荐档位；16:10 屏幕不会混入 16:9 推荐，同一尺寸不会因刷新率或实现路径重复出现。
- 缺少目标模式时提供「启用更多 HiDPI／恢复原配置」。当前开放给未旋转、未镜像的 2560×1600 外接屏，已在 Sculptor 实测 1600×1000 HiDPI / 120Hz；其他同规格屏幕仍需逐台验收，安装不等于模式已可用。
- 切换后 15 秒确认，未确认自动恢复；可手动恢复，虚拟模式退出 App 时恢复。连续切换会先等待原物理模式恢复，再选择下一条路径，避免旧镜像缓存成为错误的恢复目标。
- 保存、应用和删除物理显示器的分辨率 / 刷新率预设；兼容旧预设的分辨率数据，忽略旧硬件控制字段。
- 中英文界面、系统显示设置入口及只读 CLI 诊断。
- 使用系统浅色 / 深色背景与强调色；当前分辨率和唯一选择器优先展示，技术风险、物理详情、全部系统模式与预设折叠展示。
- 菜单栏面板宽 360 点，高度随内容增减；多屏内容超过可用高度时滚动，底部操作栏保持可见。
- 语言选择位于工具栏；主窗口最小宽度为 840 点，应用图标为 16:10 显示器与 2×2 像素方块。

不包含亮度、音量、对比度、输入源、电源、色温、Night Shift、快捷键控制、同步或定时任务；不会探测或读写 DDC。物理配置只声明真实面板像素尺寸与 macOS 缩放条目，不修改 EDID 字节或屏幕固件、不安装驱动、不要求关闭 SIP。

## 16:10 屏幕

Sculptor 2560×1600 已通过 1600×1000 HiDPI / 120Hz 实屏验收：用户确认画面铺满、无左右黑边、文字比例正常。采用真实面板尺寸加 8 字节双倍渲染尺寸，系统报告 3200×2000 渲染、两台在线显示器、无镜像。15 秒自动恢复与确认保留均通过；当前已保留此档位，不使用虚拟显示器。此前 16 字节标记格式的拉伸失败不再是默认生成路径。

使用现有模式：找到屏幕 → 在「HiDPI 分辨率」选择尺寸 → 15 秒内点击「保留分辨率」。

增加模式：点击「启用更多 HiDPI」→ 核对屏幕与目标 → 亲自完成 macOS 管理员授权 → 可先关开副屏电源并刷新，未生效再重连或重启。本机关开电源后系统模式数 93→95，无需插拔 HDMI。仅实际注册的 2× 模式进入选择器，仍要检查铺满和文字效果；App 不自动断开或重启。

实验性兼容选项：展开「实验性兼容选项」后手动选择虚拟方案。此前在本机 macOS 27.0 的 Sculptor 上验证过 1440×900、1600×1000、1680×1050、1920×1200 的 2× 虚拟渲染与 60Hz 切换、确认及恢复；这些结果不是物理覆盖方案的验收，也不证明面板无黑边。虚拟会话不保存到预设、退出时恢复、下次启动不自动重建。

## 从源码构建

- 运行：macOS 14 或更新版本。当前物理模式实测环境见 [兼容性记录](docs/compatibility-matrix.md)。
- 构建和测试：Xcode 16 或更新版本（Swift 6，含 Swift Testing），已选择对应的 Command Line Tools。
- 无外部 Swift 包依赖；默认构建不写入系统显示配置。

```bash
git clone https://github.com/rockythink/2k-hidpi-assistant.git
cd 2k-hidpi-assistant
swift test
./script/build_and_run.sh --build
```

`--build` 只构建，不关闭或启动现有 App。构建脚本优先使用本机代码签名身份，无可用身份时使用 ad-hoc 签名；本仓库不包含签名凭据或已签名安装包。

产物：`dist/HiDPIBuddy.app`，包含独立的虚拟显示器辅助程序。

验证启动：

```bash
./script/build_and_run.sh --verify
```

只读诊断与模型测试：

```bash
swift run HiDPIBuddy diagnose --all --json
swift test
```

CLI 仅提供 `help`、`list`、`status`、`get` 和 `diagnose`；模式切换在 App 中操作。

## 边界与恢复

- 物理配置写入 `/Library/Displays/Contents/Resources/Overrides/DisplayVendorID-6474/DisplayProductID-d01f`；不会写入 `/System`，系统原配置只作为只读合并模板。
- 按 Vendor/Product ID 匹配型号，影响所有同 VID/PID 屏幕，不限当前连接的这一台。保留原 plist 字段及未知缩放条目；声明 `DisplayPixelDimensions` 为真实面板宽高，只追加 8 字节双倍渲染宽高，不生成旧 16 字节标记或默认 ppmm。已有面板尺寸冲突时拒绝覆盖。
- 在 `/Library/Application Support/HiDPIBuddy` 先原子保存 root 所有的原字节备份与摘要收据，再提交产品文件。恢复原样还原安装前字节；原先没有文件时只删除本产品文件，不删除厂商目录或其他产品。
- 他方修改、损坏收据、非安全所有者/写权限、符号链接、硬链接、特殊文件或授予权限的 ACL 会阻止安装或恢复；不会强行覆盖。目录与文件分别使用 0755/0644，普通用户只读状态，只有管理员能修改。
- 安装和恢复使用固定的系统 `/usr/bin/ruby`（当前 macOS 已弃用内置 Ruby，但本机仍有 2.6.10）。缺失时在授权前报错，不使用 Homebrew/PATH 替代、不自动安装依赖。一次事务通过 macOS 管理员对话框执行，密码不进入 App；主线程不等待阻塞。
- 2026-10-08 初次 16 字节标记格式注册了模式但实屏左右黑边、文字拉长，已撤回。后续 8 字节格式加真实面板尺寸经用户授权安装，副屏电源关开后模式 93→95；默认 DisplayStore 路径完成 1600×1000 / 120Hz 的 15 秒自动恢复和用户确认保留，实屏铺满与文字比例正常。真实配置恢复流程已验证，主屏在每次切换前后模式相同。发布版已构建并启动，主窗口已捕获；临时硬件测试已删除，常规 36 项测试通过。
- 原始 NativeFormat1920×1080 不等于 CoreDisplay 的最终面板尺寸判定，不能作为尺寸覆盖是否采纳的独立依据。此前只添加尺寸的试验因保守门槛撤回，未测试其 1600×1000 输出，效果仍未知。
- 8 字节格式参考 [Crisp PR 86](https://github.com/didriksg/Crisp/pull/86)。该 PR 未合并；本项目依赖自身 Sculptor/macOS27.0.1 的实际输出与恢复验证，不宣称其他设备普遍兼容。现已切换永久生成器、保留安全备份与重校验流程；不采用该 PR 的自动软件断连逻辑。
- 虚拟路径使用私有 `CGVirtualDisplay` / CGS API，只对在线、未旋转、未加入镜像组的外接屏开放。失败会报告错误并恢复；2× 渲染缩放到面板可能使文字偏软或降低刷新率，不增加实际像素。
- 历史虚拟路径已验证自动、手动和正常退出恢复、屏幕排列恢复以及其他主屏不变；强杀或拔线恢复未实测。系统升级、其他 macOS 版本、旋转/内建屏和第三方虚拟/USB 显示方案仍需实测。
